# WB: регионы/города и `dest` для `card.wb.ru/cards/v4/detail`

Дата исследования: 2026-09-28. Все «живые» проверки выполнялись анонимно с датацентр-IP (RU-направление, 77.241.21.226). Пометки: **[L]** = подтверждено запросом сегодня; **[C]** = из общинных/зеркальных источников; **[U]** = непроверенно/требует проверки с резидентного IP.

## TL;DR

1. **Публичного JSON-эндпоинта со списком регионов без анти-бот/без токена с датацентр-IP не найдено.** `locations.wildberries.ru/get-data.json` — не существует (NXDOMAIN, никогда не архивировался) **[L]**. Есть два реальных пути: `https://common-api.wildberries.ru/api/v1/geos` (требует бесплатный API-ключ WB) **[L]** и `https://www.wildberries.ru/api/header/geos` (анонимный, но за JS-антиботом wbaas) **[L]**.
2. **Точный dest-ID для Курска с этого IP верифицировать не удалось** (сайт и все зеркала за WAF). Известные публично hub-коды: Москва `-1257786`, СПб `-1029256` и др. Ниже — три рецепта получить ID Курска за 2 минуты с обычного браузера/резидентного IP.
3. **Лимит батча `cards/v4/detail` — ровно 1000 nm_id на запрос; всё, что после 1000-го, молча отбрасывается (HTTP 200)** **[L]**. card.wb.ru не троттлит (20/20 × 200 подряд); search.wb.ru троттлит агрессивно (429 без Retry-After) **[L/C]**.
4. **Если товар недоступен/невозможна доставка в dest: товар возвращается, но `totalQuantity: 0`, а в `sizes[]` нет объекта `price` вообще** **[L]**. Неверный dest (`-1`, `999999999`) → HTTP 400 **[L]**. Без `dest` → `{"products":[]}` (HTTP 200) **[L]**.

## 1. Эндпоинты со списком регионов

### 1.1 `GET https://common-api.wildberries.ru/api/v1/geos` — официальный, по токену **[L]**

Ответ сегодня, без токена:

```http
HTTP/1.1 401
{"status":401,"statusText":"Unauthorized","title":"Unauthorized",
 "detail":"invalid API access token: empty main token",
 "requestId":"...","origin":"ag-common","timestamp":"2026-09-28T07:22:08Z"}
```

401 (а не 404) на `/api/v1/geos` при 404 на `/geos` ⇒ маршрут существует, авторизация обязательна **[L]**. Аналогично отвечают 401 и другие угаданные гео-маршруты (`/api/v1/geos/autocomplete`, `/api/v1/geos/tree`, `/api/v1/districts`, `/api/v1/regions`, `/api/v1/cities`, `/api/v1/sd3pvs/geos`) — но существование каждого из них конкретно так не доказано (401 может выдаваться широким префиксом) **[U]**.

Токен: ключ «Общий API / новый API» генерируется бесплатно в ЛК продавца: Профиль → Настройки → Доступ к API (подтверждено официальным README `wildberries-tech/api`). Передаётся в заголовке `Authorization` (без `Bearer`). Формат ответа с токеном из документации достать не удалось (см. 1.3); по общинным описаниям элементы содержат поля вида `digitalId`, `name`, `parentRegionId`, `timezone` **[C]**. **Важно: связь `digitalId` из этого списка с числом, которое подставляется в `dest`, публично не подтверждена — не полагайтесь без проверки [U].**

### 1.2 `GET https://www.wildberries.ru/api/header/geos` — анонимный, за анти-ботом **[L]**

Существует: `https://www.wildberries.kz/api/header/geos` даёт 302 → `https://global.wildberries.ru/api/header/geos` → HTTP 498 с JS-челленджем `wbaas` (`/__wbaas/challenges/antibot/...`) **[L]**. То же для `.by/.kg/.uz/.am/.ge` — все национальные витрины редиректят на `global.wildberries.ru` и требуют прохождения анти-бота **[L]**. С резидентного IP (браузер) эндпоинт, по общинным сведениям, отдаёт JSON со списком регионов/городов текущего сайта — формат ответа с резидента не снят **[U]**. Для бота на сервере это тупик без решателя челленджей; у WB стоит JA4-фильтрация (в их официальном org есть `wildberries-tech/ja4-nginx-module`) **[C]**.

### 1.3 Что НЕ существует / недоступно **[L]**

- `locations.wildberries.ru` — **NXDOMAIN**; в Wayback нет ни одного снапшота `get-data.json` (404 на archive.ph, never-crawled в Common Crawl) ⇒ эндпоинт выдуман/мёртв.
- `user-geo-data.wb.ru` — NXDOMAIN. **`user-geo-data.wildberries.ru` резолвится** (185.138.255.1) — живой сервис; перепробовал ~15 путей (`/get_geo_info`, `/regions`, `/getGeoInfo`, POST с координатами и т.п.) — все 404 с пустым телом. Точный путь неизвестен (в dev.to-разборе фигурировал `get_geo_info`, но и там автор его не проверил) **[U]**.
- `search.wb.ru/*`, `catalog.wb.ru/*` — 403 по IP (WAF, даже с полным набором браузерных заголовков и TLS-фингерпринтом curl; curl-фингерпринт палится — см. dev.to §6 «ваш HTTP-клиент — часть отпечатка»).
- `dev.wildberries.ru` — 498 с датацентр-IP; снапшотов в Wayback не получил (archive.org в момент исследования лежал/503, затем 429 по нашему IP; Common Crawl индекс жив, но `api/header/geos` не краулился никогда).

## 2. Какой `dest` у Курска

Точный ID с этого окружения **получить не удалось** (см. 1). Что установлено:

- Пространство значений `dest` cards/v4 — не «номера субъектов РФ» и не маленькие ID регионов. Это коды хабов доставки, в т.ч. отрицательные 32-битные числа. Подтверждённые живыми запросами значения и их имена (cross-check: цены различаются по dest):
  - Москва: `-1257786` **[L+C]** (используется как «дефолт» на витрине)
  - Санкт-Петербург: `-1029256` **[C: glama/ru-marketplace-mcp; цена 6 064 000 vs 6 167 900 у Москвы — dest реально влияет [L]]**
  - Краснодар: `-1059500`, Екатеринбург: `-1113276`, Новосибирск: `-1221148`, Хабаровск: `-1221185` **[C: константы `DESTINATIONS` в glmn/wb-private-api; для -1221185 подтвердил живым запросом [L]]**
- Малые целые (1..120) endpoint **принимает без ошибки**, но все 6..120 дают одинаковую «обобщённую» цену (6 670 400 для тестового nm), 1..5 и 0 — без цены. ⇒ Подставлять официальные коды субъектов РФ (у Курской области 46) в `dest` **нельзя** — получите не курские цены **[L]**.
- Связь с сайтом: URL-параметр `?to=` на wildberries.ru и значение `dest` в XHR-запросах сайта (search.wb.ru / card.wb.ru) — одно и то же число; выбранный регион хранится в localStorage/куке сайта **[C — общинный консенсус, с датацентр-IP не подтвердить [U]]**.

### Рецепты получить dest Курска (2 минуты)

1. **Браузер**: открыть wildberries.ru с резидентного IP → сменить регион на «Курск» → в DevTools на любой странице каталога посмотреть `?to=` в адресной строке и/или параметр `dest=` в XHR к `search.wb.ru`/`card.wb.ru`. Проверить: `curl "https://card.wb.ru/cards/v4/detail?appType=1&curr=rub&dest=<ID>&nm=<любой nm с остатком>"` — цены должны совпасть с курскими.
2. **Токен**: `curl -H "Authorization: <ключ>" https://common-api.wildberries.ru/api/v1/geos` — пройтись по списку и подобрать Курск/Курскую область; перепроверить candidate-ID методом «цена совпадает с витриной» (рецепт 1).
3. **Эмпирический скан** (если доступа к браузеру нет): перебор candidate-значений и сравнение цены известной позиции; для Курска код лежит в том же регистре, что и hub-коды других городов — угадывание перебором всего int32 нереалистично, поэтому 1 или 2 предпочтительны.

## 3. Лимиты `cards/v4/detail`

- **Батчинг**: `nm` — список через `;` (не через запятую). **Сервер обрабатывает ровно первые 1000 id**; id с позиции 1001+ молча игнорируются, HTTP остаётся 200. Проверено бинарным поиском: position 1000 — возвращается; 1001/1005/1008/1012/1025/1100/1250/1300/1400/1500 — не возвращается. URL на ~54 КБ (5000 id) прошёл бы, но Windows-curl упёрся в лимит командной строки; на сервере с обычными ОС-лимитами — без проблем **[L]**.
- Невалидные/несуществующие nm в батче **исключаются без ошибки и без плейсхолдера**: сверять результат нужно по `products[].id`, никогда `len(products) != len(ids)` **[L/C]**.
- Практический вывод: бить пачки ≤1000 жёстко; для надёжности парсить `;`-строки и рефлексивно проверять, что каждый id вернулся (отсутствие = «нет карточки для этого dest/вообще» — см. §4). Клиентский дефолт в общинных либах — 100 на запрос (glama ru-marketplace-mcp) **[C]**.
- **Rate limit анонимных запросов**:
  - `card.wb.ru`: 20 последовательных запросов без задержки — 20×200; параллельные тесты dev.to (2026-07): 30/30×200. Агрессивного троттлинга нет, но gateway `wbaas` выдаёт заголовок `x-pow: status=invalid;challenge=...` — proof-of-work челлендж, **в момент проверки не применяется** (данные приходят всё равно). Может включиться в любой момент **[L/C]**.
  - `search.wb.ru`: наоборот — жёсткий троттлинг: холодный IP может получить 429 сразу; 30 запросов/69 с — 13×200+17×429; 429 без `Retry-After`; плюс «подменный» 200-ответ другой схемы. С нашего IP — 403 всегда. Для прайс-радара это аргумент строить discovery по оф. токен-эндпоинтам или кэшировать nm-листы, а не долбить search **[C: dev.to замеры 2026-07; [L] — 403]**.
  - Официальные публичные лимиты по анонимным хостам нигде не документированы **[U]**.

## 4. Поведение при недоступности товара в `dest`

Матрица живых ответов (nm=1280469586;824935779;497398643, кросс-проверено дважды):

| dest | HTTP | Поведение |
|---|---|---|
| `-1257786` (Мск) | 200 | полный товар: `totalQuantity:9`, `sizes[].price.product:6167900` |
| `-1029256` (СПб) | 200 | те же товары, **другие цены** (6064000) |
| `-1221185` (Хабаровск) | 200 | товары есть, но `totalQuantity:0` и **объекта `price` в sizes нет вовсе** |
| `0`, `1` | 200 | то же, что «нет поставки»: qty=0, цен нет |
| `6..120` | 200 | товары + цены, но все идентичны (обобщённая поставка) |
| `-1`, `999999999`, `-999999999` | **400** | пустое тело — невалидный формат dest |
| (dest не передан) | 200 | `{"products":[]}` — пусто даже для валидных nm |
| несуществующий nm в батче | 200 | просто отсутствует в `products[]` |

Выводы для бота:

1. `dest` **обязателен** в каждом запросе — без него cards/v4 отдаёт пустой список, а не ошибку.
2. «Нет доставки в регион» кодируется **отсутствием цены** + `totalQuantity:0` (Wildberries выражает недоступность умолчанием, а не null/ошибкой — та же привычка, что и с выброшенными id в батчах **[C: dev.to]**). Не считать такую позицию «цена пропала из-за бага»: это валидный сигнал out-of-stock в регионе.
3. Неверный формат dest — чистый 400: валидировать свой справочник ID нужно на заведомо пустом nm (чтобы 400 не путался с empty-200).
4. Цены в ответе — в копейках **[C: dev.to; согласуется с [L]-наблюдениями]**.
