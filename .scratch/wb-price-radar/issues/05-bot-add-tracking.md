# 05: Бот: добавление Отслеживания по Артикулу/ссылке с inline-подтверждением

**What to build:** Пользователь присылает Артикул или ссылку на карточку — бот показывает предпросмотр Товара (фото, название, Финальная цена в его Регионе, ссылка) с кнопками ✅ «Добавить» / ✖ отмена; подтверждение создаёт Отслеживание с Ценой сравнения = Финальная цена на момент добавления (ADR-0003). Отказы: «Товар не найден» для missing, вежливые подсказки для ambiguous и короткой ссылки `go.wb.ru`, подсказка для дубля, вежливый отказ при лимите 100 активных Отслеживаний. `/start` — приветствие, инструкция, ensure_user с dest по умолчанию; `/help` — список команд. Payload лежит в callback data, глобальной state-машины диалога нет (§2.5). Тексты и UX-контракты — пользовательские истории 1–15 в spec.

**Blocked by:** 02 (extract_sku + WBClient), 03 (Store), 04 (NotifySender)

**Status:** accepted

- [ ] `/start`: приветствие + инструкция + `ensure_user` с Регионом по умолчанию; `/help` с командами и форматами добавления
- [ ] Текст/ссылка → `extract_sku` → карточка через `MarketplaceClient` в dest пользователя → предпросмотр (фото, название, Финальная цена, ссылка) + inline ✅/✖ без глобального state
- [ ] «Да» → `upsert_card` + `add_tracking` с Ценой сравнения = Финальная цена на момент добавления; «нет» → ничего не создаётся
- [ ] missing → «Товар не найден»; ambiguous / short_link → отказ с просьбой уточнить Артикул или прислать полную ссылку
- [ ] Дубль (`find_tracking`) → сообщение-подсказка без создания; лимит (`can_add`, 100) → вежливый отказ с объяснением
- [ ] Handler остаётся тонким: ввод → domain/Store → форматирование; бизнес-решений внутри нет (§2.5)
- [ ] Handler-тесты на fake-швах: routing ввода, тексты отказов, границы лимита 99/100/101, дубль (spec, «Решения по тестированию» п.7)
